# 白板系統

## 這是什麼

每個對話 session 恰有一塊白板，裝**這個 session 專屬**的東西——規則、目標、進度、聊到哪。開場必讀，讀完向主人宣告。

**日常讀板不需要本 skill。** 讀板流程寫在 `C:\Users\Shinemind\AGENTS.md` B1——那是每輪真自動注入的位置。本 skill 只在你要**改這套系統**、或要查「這塊板有冇按規矩寫」時用。

**白板的存在理由（2026-11-09 主人原話）**：我的記憶只穩定保持約 4 輪對話。做著做著會忘目標、忘做到哪。主人下一輪開始跟我聊俄烏戰爭聊 100 輪，到第 101 輪返回來做正事，我依然要記得：已做什麼、未做什麼、下下步、下下下步、目標是什麼、怎麼找回當前正在做的專案。**這白板才叫用得其所。**

---

## 白板骨架（11 欄，寫死）

**這是本 skill 唯一強制項。** 每塊板必須有這 11 欄，標題一字不改，順序不改。冇骨架＝各寫各的＝亂寫。

```markdown
# 白板 — <session_id>

> **最後更新**：<YYYY-MM-DD HH:MM>｜**輪次**：第 <N> 輪
> 完整路徑：C:\Shinemind\白板\<session_id>.md

## ① 專案專屬規則〔主人填，我只讀不改〕
## ② 目標／要解決什麼
## ③ 當前專案
## ④ ToDo List〔專案鏡像，雙向同步〕
## ⑤ 任務清單〔session 調度〕
## ⑥ 已完成〔只留結論，細節住專案〕
## ⑦ 上一回做了什麼
## ⑧ 近 5 輪對話〔滑動窗口〕
## ⑨ 未做／下一步
## ⑩ 下下步
## ⑪ 怎麼找回當前狀態

## 歸檔（不讀）
```

> **舊制已廢**：2026-11-09 前的「## 現行（每輪讀這段）／## 歸檔」兩區制，由 11 欄骨架取代。兩區制的「現行」變成 ①-⑪，「歸檔」保留。

### 逐欄規格

| 欄 | 裝什麼 | 幾時更新 | 上限／禁忌 |
|---|---|---|---|
| **檔頭** | 最後更新時間、輪次 | **每輪必改** | 時間唔准估，要寫實際 |
| **①** | 主人親自寫的專案規矩 | **只有主人改** | 我一個字都唔准動 |
| **②** | 目標，一句話講清要解決什麼 | 目標變才改 | 唔准寫成任務清單 |
| **③** | 當前專案：名稱／根目錄／主檔／ToDo 來源／最後在專案內做什麼 | 轉專案或路徑變 | **全部完整絕對路徑**，唔准寫「同上」 |
| **④** | 未完成的待辦，**鏡像自專案 ToDo** | 專案 ToDo 一改即同步 | 完成即移去 ⑥；標明鏡像來源路徑 |
| **⑤** | session 層多專案調度：處理中／排隊第1／排隊第2 | 任務序變才改 | 一個 session 可掛多個專案 |
| **⑥** | 已完成項目，**只留結論一行一項** | 完成一項即加 | 細節住專案／日誌；呢度唔寫過程 |
| **⑦** | 上一回做了什麼，**≤3 句** | **每輪必改** | 只講結論；超過 3 句＝寫成日誌 |
| **⑧** | 近 5 輪對話（講什麼／做了什麼／完成什麼） | **每輪必改**，新進舊刪 | 永遠 5 條（主人原話「上5輪」） |
| **⑨** | 未做什麼、下一步 | 每輪核對 | 阻塞的要標誰出手【主人】 |
| **⑩** | 下下步 | ⑨ 完成後即補 | 唔知就寫「待定」 |
| **⑪** | 怎麼找回當前狀態：路徑、停在哪個檔第幾節 | 位置變才改 | 只放指針，唔放內容 |

### ③ 當前專案 的格式（最重要一欄）

```markdown
## ③ 當前專案

- **專案名**：北上攻略
- **根目錄**：`D:\Illusky\工作區\北上攻略\`
- **主檔**：`D:\Illusky\工作區\北上攻略\攻略.md`
- **ToDo 來源**：`D:\Illusky\工作區\北上攻略\to do list.md`（④ 的鏡像來源）
- **最後在專案內做什麼**：白名單 14 站排序完成，HTML 待同步
```

無專案時寫：`無（本 session 未開專案）`——④ 就放 session 自己的待辦，並標「非鏡像」。

### ⑦ 上一回 vs ⑧ 近 5 輪 的分工

兩個都要，唔可以合併：

- **⑦ 上一回**＝只講**最近一次**做什麼（重啟用，一眼接上）
- **⑧ 近 5 輪**＝**趨勢**（離題偵測用）。離題 100 輪傾俄烏，⑧ 會顯示「最近 5 輪全部係俄烏」——我一眼知道要返正題；⑦ 只會顯示「上一輪傾俄烏」，分不出是剛開始離題還是離題很久

### ⑧ 的格式

```markdown
## ⑧ 近 5 輪對話〔滑動窗口〕

| # | 時間 | 講什麼 | 結果 |
|---|---|---|---|
| -5 | 20:22 | 白板路徑生效範圍 | 查實舊 session 唔跟，答未修好 |
| -4 | 20:35 | 白板寫作品質 | 出 11 欄骨架方案 |
| -3 | 21:02 | 主人拍板 A/B/C | 開工 |
| -2 | 21:20 | 重寫 SKILL.md | 完成 |
| -1 | 21:35 | 遷移舊板 | 進行中 |
```

每輪收尾：加新行（-1），舊行編號往前推，最舊（-5）刪走。

### 為什麼廢除日期流水節

舊板用「## 2026-11-09 19:26 · 某某」逐日記帳。實測五塊板有四塊係咁，最長 4,503 chars。

問題：**流水帳會越寫越長，而「我而家要做什麼」要掃完全部才找得到。** 離題 100 輪返嚟，見到一堆日期，唔知邊個係當前。

**白板不是日誌。** 日誌住 `C:\Users\Shinemind\.hermes\進化控制台\進化日誌\evolution-log.md`（用 `append_log.py`）。白板的時間維度只有兩個：⑦ 上一回、⑧ 近 5 輪。

## 每輪強制更新報告（2026-11-09 主人令）

**問題**：白板是死板——主人不講，我不更新；有冇更新，主人驗不到。

**解法**：每輪回覆壓尾，取代舊「宣佈白板」，變成**逐項交代**：

```
> 白板：`<id>`｜完整路徑：`C:\Shinemind\白板\<id>.md`
> 更新：④✅ ⑦✅ ⑧✅ ⑨✅
> 未變：①②③⑤⑥⑩⑪｜理據：①主人未改規則 ②目標未變 ③專案未轉 ⑤任務序無新決策 ⑥本輪無新完成項 ⑩承接⑨ ⑪位置未變
> 提醒下一輪的我：記得讀自己的白板。
```

**四條硬規矩**：

1. **11 項逐項交代，一項都唔准靜默。** 冇出現在「更新」或「未變」＝漏報。
2. **每項未變都要寫理據。** 講唔出理據＝該項本身有問題（例如 ② 目標唔知係咩）。
3. **❌ 做唔到要講原因**，唔准假裝 ✅。例如「④ 專案 ToDo 檔唔存在，無法鏡像」。
4. **理據要具體**，唔准寫「無變化」「不需要」四個字了事。

**為什麼要咁煩**：主人原話——「我不說，就不去更新」。報告就是逼我每輪摸一次每一欄，順手就更新了。唔報＝唔查＝死板。

## 防膨脹：不需多，只需夠

**唔設總字數上限**（那是自造假尺）。靠四條結構規則：

| 規則 | 內容 |
|---|---|
| ④ ToDo 只放未完成 | 完成即移去 ⑥——白板唔做存檔 |
| ⑥ 一項一行 | 只寫結論，過程住專案／日誌 |
| ⑦ ≤3 句 | 超過＝寫成日誌 |
| ⑧ 永遠 5 條 | 多一條刪一條 |
| ⑪ 只放路徑 | 唔放內容 |

**判準**：任何一欄寫到要向下捲才看完，該欄細節就搬去專案檔，白板只留指針。

| 白板放 | 白板唔放（屬專案內容） |
|---|---|
| 目標（一句） | 架構圖、方案比較、成本明細 |
| ToDo（專案鏡像） | 全部測試數據、log、錯誤訊息 |
| 已完成的結論（一行） | 查證過程、文獻、URL 清單 |
| 下一步／阻塞點（誰出手） | 已完成工作的逐項細節 |

**判斷標準**：呢一行，隔 100 輪後仲有冇用嚟決定「下一步做咩」？冇 → 搬去專案。

## 防死板：讀板先核時效

**每輪開場讀板（B1），第一件事唔係讀內容，係核對時效：**

1. 讀檔頭「最後更新」時間
2. 同上一輪對話時間比
3. **落後 → 即場補寫，唔准讀著舊板開工**

死板的定義：**檔頭時間落後於 session 實際對話時間**。呢個唔靠自覺，靠每輪機械核對。

## 怎麼建

新 session 第一次開場，`AGENTS.md` B1 第 3 步會叫你建。做法：

```bash
ID=$(echo $HERMES_SESSION_ID)
mkdir -p "C:/Shinemind/白板/歸檔"
ls "C:/Shinemind/白板/$ID.md" 2>/dev/null || echo "要建"
```

**照上面「白板骨架」11 欄逐欄填。** 第一次建板時，未知的欄寫具體的「暂无」而唔係留空：

- ② 目標：`待主人下達`
- ③ 當前專案：`無（本 session 未開專案）`
- ④ ToDo：`非鏡像——本 session 未有專案`
- ⑨ 下一步：`等主人講任務`
- ⑩ 下下步：`待定`
- ⑪ 找回：`本板即為當前狀態，未有專案`

建完**即刻加一行到 `白板索引.md`**——五欄，最後一欄「完整路徑」照 `C:\Shinemind\白板\<id>.md` 填，**唔准留空**。然後照樣讀：建完即讀，這一輪就有板。

## 為什麼不用 RULES.md / SESSION-RULES

2026-11-09 實測：

| 檔 | 自動注入 | 實情 |
|---|---|---|
| `AGENTS.md` | ✅ | `agent/coding_context.py:86` `_CONTEXT_FILES` |
| `RULES.md` | ❌ | 要人主動讀，而「誰提醒」無解 |
| `SESSION-RULES-<id>.md` | ❌ | Hermes 源碼**零** `SESSION-RULES` 字串，從未載入過 |

「每輪必讀」的東西住在不會自動出現的檔＝等於沒有。所以整條鏈只能掛在 `AGENTS.md` 這一個點上。

**補充（2026-11-09 源碼實證）**：`agent/system_prompt.py` L476 註明 context files 是 **API-call time 每次重新讀**，不進 cached system prompt。所以 `AGENTS.md` 一改，**所有 session 下一輪即刻拿到新版**——包括開著未關的舊 session。舊 session 唔跟規矩唔係「收不到」，係慣性。
