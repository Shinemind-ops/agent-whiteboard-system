### B1 · 開場：讀自己的白板

**每一輪對話，無論任務、閒聊、還是任何事情，第一件事按順序做：**

1. **確認身份**——跑 `echo $HERMES_SESSION_ID`。這個環境變數就是「我是哪個 session」的硬事實，不是猜的。
2. **開自己的白板**——`<白板根>\<那串 id>.md`
3. **不存在就建**（禁止零塊）——照 11 欄骨架建（見 skill `whiteboard-system`），每欄填「待定」都算有板，然後即刻讀。禁止建空檔。
4. **核時效＋機械驗證**——讀檔頭「最後更新」時間，同上一輪對話時間比。**落後＝死板，即場補寫，唔准讀著舊板開工。** 再跑 `python <hermes 目錄>\scripts\verify_whiteboard.py --session $HERMES_SESSION_ID`：非 PASS 即場修到 PASS，唔准帶 FAIL 開工。
5. **讀 11 欄**（①-⑪，骨架住 skill `whiteboard-system`）——「歸檔」區不讀。
6. **開場第一句宣告**（兩行，格式寫死，唔准自創）：

   ```
   白板 <id> 已讀｜目標：<X>｜要點：<三句>｜輪次：第 <N> 輪｜
   完整路徑：<白板根>\<id>.md
   ```

   id 寫錯＝讀錯板，要點寫不出＝沒讀，**路徑漏寫＝主人搵唔到板**。這是給主人驗的。

**白板是什麼**：這一輪的恢復點。我的記憶只穩定約 4 輪——白板要令我隔 100 輪（中間聊別的）回來，仍然記得：目標、已做什麼、未做什麼、下一步、下下步。**11 欄骨架，每欄只放夠用**（骨架定義住 skill `whiteboard-system`）。 架構／數據／風險／查證記錄屬專案內容，住專案檔；白板只放指針（專案完整路徑）。每個 session 恰有一塊，最多一塊，禁止零塊。

**ToDo 是鏡像**：白板內的 ToDo 從專案內 ToDo List 複製一份（同一批編號）；改任何一邊，即場改另一邊，兩份永遠同一狀態。要主人出手的步驟，標明【主人】。

**白板住哪**：`<白板根>\`（對照表 `白板索引.md`；已結束的進 `歸檔\`）

**舊制已退役**：`RULES.md` 與 `SESSION-RULES-<id>.md` 不再使用——它們住在不會自動注入的地方，實測從未載入過一次。內容已併入本檔與白板。架構與操作見 skill `whiteboard-system`。
